# Data schema

`data/` is the single source of truth for the site. This document defines every
file and field, the controlled vocabularies, and the rules `scripts/validate.mjs`
enforces. **Extend a vocabulary here first, before using a new value in data.**

Three kinds of file:

| File | What it is |
|---|---|
| `data/venues.json` | The registry of chapels. Compiled by hand from each venue's website; see `docs/sources-survey.md`. Not re-generated by the pipeline. |
| `data/index.json` | The list of terms and which one is "current". |
| `data/terms/<termId>.json` | One file per term: every sung service that term, plus per-venue status. Produced by the `update-termcard` skill (later); `2026-TT.json` is currently a hand-built fixture. |

Term ids are `<year>-MT` \| `<year>-HT` \| `<year>-TT` (Michaelmas / Hilary / Trinity),
e.g. `2026-MT`. Service ids are `<date>-<venueId>-<HHMM>`, e.g.
`2026-05-10-magdalen-1800`.

---

## `data/index.json`

```json
{
  "current": "2026-MT",
  "termFiles": ["2026-TT"],
  "terms": {
    "2026-MT": { "name": "Michaelmas 2026", "weekOneSunday": "2026-10-11", "lastSaturday": "2026-12-05" }
  }
}
```

| Field | Meaning |
|---|---|
| `current` | Term id the site shows by default. May name a term with no term file yet (e.g. before a term's lists are published) — validation warns, does not error. |
| `termFiles` | Optional array. The term ids that have a `data/terms/<id>.json` file **right now** — how the site knows what to fetch. Distinct from `terms`: a term file may exist for a term not in `terms` (the `2026-TT` fixture), and `terms` may list a term whose file isn't out yet. The site fetches **exactly** the ids in `termFiles` (it still tolerates a 404 on any of them). Validation errors if an entry has no matching file or the file's `term.id` disagrees, and warns if a `data/terms/*.json` on disk is missing from `termFiles`. |
| `terms` | Object keyed by term id. |
| `terms.<id>.name` | Human name, e.g. `"Michaelmas 2026"`. |
| `terms.<id>.weekOneSunday` | ISO date of the Sunday of 1st Week (= the start of Full Term). Must be a Sunday. |
| `terms.<id>.lastSaturday` | ISO date of the Saturday of 8th Week (the "To" date on ox.ac.uk). Must be a Saturday, after `weekOneSunday`. |

`data/index.json` `terms` currently lists only terms whose Full-Term dates are
published on ox.ac.uk (Michaelmas 2026 onward). The `2026-TT` fixture is **not** in
`terms` (see "Term resolution" below) but it **is** in `termFiles`, so the site
loads it.

### Term resolution (`scripts/oxweeks.mjs`)

Oxford-week arithmetic needs a term's `weekOneSunday`. `oxweeks.mjs` resolves a
term id by looking first in `data/index.json` `terms`, then — if absent — in that
term's own file (`data/terms/<id>.json` → `term` block). This is what lets the
`2026-TT` fixture work without a Trinity 2026 entry in `index.json`. If a term
appears in both, the dates must agree (validation errors otherwise).

`oxweeks.mjs` exports:

- `dateForWeekDay(termId, week, dayName)` → ISO date. `week` is `-2..10`
  (0th Week = the week before 1st Week). `dayName` is `Sun`..`Sat` or the full name.
- `weekDayForDate(termId, isoDate)` → `{ week, day }`. `week` may fall outside `0..9`.
- `termForDate(isoDate)` → the term id whose weeks `-2..10` contain the date, or `null`.

Weeks run **Sunday to Saturday**. Never do this arithmetic by hand.

## `data/terms/<termId>.json`

```json
{
  "term":        { "id": "2026-MT", "name": "Michaelmas 2026",
                   "weekOneSunday": "2026-10-11", "lastSaturday": "2026-12-05",
                   "timezone": "Europe/London" },
  "generated":   { "at": "2026-10-04T17:12:00Z", "by": "update-termcard",
                   "notes": "free text", "sources": "sources/2026-MT/" },
  "venueStatus": { "<venueId>": { … } },
  "services":    [ { … } ]
}
```

### `term`

| Field | Meaning |
|---|---|
| `id` | Term id. Must equal the filename stem. |
| `name` | Human name. |
| `weekOneSunday`, `lastSaturday` | As in `index.json`. Must agree with `index.json` if the term is listed there. |
| `timezone` | Always `"Europe/London"`. |

### `generated`

| Field | Meaning |
|---|---|
| `at` | ISO timestamp the file was produced. |
| `by` | What produced it (`"update-termcard"`, `"hand-built fixture"`, …). |
| `notes` | Free text: what's in scope, what was skipped, anything unusual. |
| `sources` | Optional: path to the committed raw lists for this term (`sources/<termId>/`). |

### `venueStatus`

Object keyed by `venueId` (must be a venue in `venues.json`). Every venue in the
registry should appear (validation warns if one is missing). One entry:

| Field | Meaning |
|---|---|
| `status` | Controlled — see below. |
| `sourceUrl` | The list URL that was fetched (or attempted). Required when `status` is `published`. |
| `fetchedAt` | ISO timestamp of the fetch, or `null`. |
| `services` | Count of this venue's entries in `services[]`. Must match exactly. |
| `note` | Free text or `null` — e.g. why a list is missing, what was reconstructed. |

### `services[]`

One object per sung service. All 17 fields are required; use `null` where a value
does not apply. Nothing about a service is ever guessed — if the list does not say,
the value is `null`.

| Field | Meaning |
|---|---|
| `id` | `<date>-<venueId>-<HHMM>`. Unique within the file. If `time` is `null`, the `-<HHMM>` part is a placeholder but the `<date>-<venueId>-` prefix still holds. |
| `venueId` | A venue in `venues.json`. |
| `date` | ISO date, Europe/London. Must lie within `[weekOneSunday − 28d, lastSaturday + 28d]`. |
| `time` | `"HH:MM"` 24-hour, **or `null`** if the list gives no time and the venue has no fixed pattern. |
| `week` | Oxford week (integer). Must equal `weekDayForDate(term, date).week`. |
| `day` | `Sun`..`Sat`. Must equal `weekDayForDate(term, date).day`. |
| `type` | Controlled — see below. |
| `title` | The list's own wording for the service, verbatim (e.g. `"Choral Evensong (Consort of Voices)"`). |
| `occasion` | The list's wording for the feast/occasion, verbatim, else `null` (e.g. `"Ascension Day"`). |
| `choir` | Set **only** when the singers are **not** the venue's own choir, e.g. `"Visiting choir: Schola Cantorum"`. The venue's own sub-groups (choristers, clerks, consort) are not a different choir — leave `null` and put the wording in `title`. |
| `music` | Array of music items — see below. |
| `musicStatus` | Controlled — see below. |
| `preacher` | Verbatim, else `null`. |
| `notes` | Verbatim remarks from the list (e.g. `"Followed by drinks in the antechapel"`), else `null`. |
| `source` | `{ url, fetchedAt, locator }` — the document the entry came from, the fetch time, and where in it (`"p.2, 1st Week"` / `"PDF p.10, '12 TUESDAY'"`). `url` is required and non-empty. `locator` may be `null`. |
| `confidence` | `high` \| `medium` \| `low` — see below. |
| `parserNote` | The update process's own explanation of any interpretation (`"time taken from venue pattern"`, `"'MASS' recorded under slot 'setting'"`), else `null`. Never list content; never shown to end users as such. |

### `services[].music[]`

| Field | Meaning |
|---|---|
| `slot` | Controlled — see below. |
| `text` | **Verbatim from the list, whitespace normalised.** This is the record. Never empty. |
| `composer` | Optional. A search/display extra — must never be the only place the information lives. |
| `title` | Optional. As `composer`. |
| `label` | **Only** on `slot: "other"`, and then required: the list's own heading for the line (`"Antiphon"`, `"Final Responses"`, `"Organ"`). |

Scripture readings, sermons and non-musical items are **not** recorded in `music[]`
— there is no slot for them.

## Controlled vocabularies

### `services[].type`

| Value | Use |
|---|---|
| `choral-evensong` | The evening Office sung by a choir (canticles to a setting, an anthem). Also covers a list's "Choral Evening Prayer". |
| `sung-evensong` | Evening Office with simpler/congregational sung parts, no full choral setting. |
| `said-evensong` | Spoken; no music. |
| `choral-matins` | The morning Office sung by a choir. |
| `choral-eucharist` | Sung/Choral Eucharist, Mass, Communion, Sung Eucharist. |
| `compline` | Compline / Night Prayer, sung. |
| `special` | Carol services, requiems, commemorations, Lessons & Carols, and the like. Put the list's wording in `title`. |
| `other` | Anything else the list names (e.g. "Choral Vespers"). Keep the list's wording in `title`. |

### `services[].music[].slot`

`introit` · `responses` · `psalm` · `canticles` · `magnificat` · `nunc-dimittis` ·
`anthem` · `motet` · `hymn` · `office-hymn` · `setting` · `voluntary` · `other`.

- Use `canticles` when the list gives the evening canticles as one entry; use
  `magnificat` / `nunc-dimittis` when it splits them (e.g. different composers).
- `setting` is the Mass/Communion setting.
- `other` carries the list's own heading in `label` (e.g. `"Antiphon"`, `"Alleluia"`,
  `"Final Responses"`, `"Organ"` for a pre-service organ piece).

### `services[].musicStatus`

| Value | Use |
|---|---|
| `published` | The music is known and recorded. `music[]` must be non-empty. |
| `not-yet-published` | The service is known but its music has not been published yet. |
| `not-parsed` | The music exists in the source but has not been transcribed. |
| `no-music` | A said service, or one the list marks as without choir. |

### `venueStatus[].status`

| Value | Use |
|---|---|
| `published` | A current list was found and read. |
| `not-yet-published` | The venue publishes a list but this term's is not up yet. |
| `not-found` | Expected a list, could not locate one this time. |
| `fetch-failed` | Found a URL but the fetch failed. |
| `not-parsed` | Fetched but not yet transcribed. |
| `no-list` | The venue never publishes a term music list. |

### `services[].confidence`

| Value | Use |
|---|---|
| `high` | Unambiguous in the source. |
| `medium` | Some interpretation (e.g. a time inferred from the venue's pattern, a slot assigned by position). |
| `low` | Needs a human look. The site marks these. |

## Validation rules (`scripts/validate.mjs`)

Run `node scripts/validate.mjs` (errors → exit 1) or `--strict` (warnings also → exit 1).

**Errors:** unknown or missing fields anywhere; a service `id` that is not unique or
does not match `date`/`venueId`/`time`; a `venueId` (in a service or `venueStatus`)
not in `venues.json`; a `date` that is not ISO or is outside
`[weekOneSunday − 28d, lastSaturday + 28d]`; a `time` that is not `HH:MM` or `null`;
a `week` or `day` that disagrees with the date (per `oxweeks`); any value outside a
controlled vocabulary; an empty `music[].text`; a missing `source.url`; a service
with `musicStatus: "published"` and an empty `music[]`; a `label` on a non-`other`
slot, or a missing `label` on an `other` slot; a `venueStatus` count that does not
match the number of that venue's service objects; term dates that disagree between
`index.json` and a term file; `term.id` not matching the filename; `timezone` not
`Europe/London`.

**Warnings:** a venue in `venues.json` absent from `venueStatus`; a service dated
outside 0th–9th Week; a `published` venue with noticeably fewer services than its
`typicalPattern` implies; any `confidence: "low"`; two services at one venue within
30 minutes; a term file whose id is not in `index.json`; `current` naming a term
with no file.

`index.json` `termFiles` (if present) must be an array of strings; each must have a
`data/terms/<id>.json` whose `term.id` matches (**error** otherwise).

## How to add a venue

1. Add the venue to `data/venues.json` (`id`, `name`, `chapel`, `musicList`,
   `typicalPattern`, …) following the existing entries. Record where you looked in
   `docs/sources-survey.md`.
2. From then on the venue may appear in any term file's `venueStatus`. Until a list
   is read, give it `status: "not-parsed"` (or `no-list` / `not-found` as appropriate).
3. If the venue's list uses a heading or service type not covered above, **add it to
   the relevant vocabulary in this file first**, then use it in data.
